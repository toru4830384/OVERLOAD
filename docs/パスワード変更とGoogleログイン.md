# パスワード変更・Googleログインの導入状況

2026-11-10時点。V4移行と必要な実行権限の追加が完了し、公開更新を準備しています。

## 実装内容

- プロフィールに「現在のパスワード」「新しいパスワード」「確認」の変更欄を追加。新しいパスワードは12〜128文字です。
- 現在のパスワードを確認してからハッシュを更新。認証世代を進め、全端末のセッションを失効させます。競合で古いセッションが再保存されてもAPIで拒否します。
- 同じ利用者の識別情報・下書き保存先は変更しません。変更・再ログイン後もこの端末の下書きを復元します。
- Google公式ボタンとサーバー側の署名検証を追加。Googleの発行元・対象クライアント・有効期限・nonceを照合します。
- 既存ユーザーは、ログイン中に現在のパスワードを確認してGoogleを連携すると、同じ記録へGoogleから戻れます。メールアドレスの一致だけで既存アカウントを結合しません。
- Googleで初めて登録する場合は、プロフィールを本人が入力します。架空の体重・性別・パスワードで補いません。
- Googleで作成したアカウントにはOVERLOAD用のパスワードはありません。今回の機能は、そのアカウントへのローカルパスワードの追加やGoogle連携の解除には対応しません。
- Google連携前に既存のID・パスワードを忘れた場合、Googleだけで既存データを復旧する機能ではありません。忘れる前の連携が必要です。

## 設定

`OVERLOAD_GOOGLE_CLIENT_ID` にGoogleのWebアプリ用クライアントIDを設定します。未設定時はGoogleログインが無効になり、通常のログインとパスワード変更を利用できます。クライアントシークレット・Googleのパスワードはアプリに渡しません。

Google Cloudで、OVERLOAD専用プロジェクト・Google Auth Platformの設定・WebクライアントIDを準備します。承認済みJavaScript生成元は本番の `https://overload-cqtb.onrender.com` とし、開発用には別クライアントを使います。Google公式のボタンとJavaScriptコールバックを使うため、今回の構成でリダイレクトURIは使いません。

サポートメールはGoogleの同意画面に表示されます。使用するアカウントと公開してよい問い合わせ先を所有者へ確認してから設定します。Gmail・Drive・連絡先などへの権限は要求しません。

公開用のホームページとプライバシー説明を用意し、Google側の公開状態・必要なブランド確認を管理画面で確認します。クライアントIDを作っただけで一般公開の動作確認を完了したとは扱いません。カード登録・有料サービスの有効化は行いません。

## 本番反映の順序

1. 最新バックアップの日時と復旧手段を確認。現在の公開版とDB移行履歴を記録します。
2. 所有者の非表示パスワード入力で、使い捨てTiDBスキーマにV4移行・既存データ保持・認証の結合テストを実施します。既存業務スキーマはテスト対象にしません。
3. 明示的な承認後、本番 `overload_app` をV3からV4へ移行します。既存のハッシュ・下書き識別情報・記録は更新しません。V4は認証世代列を追加し、パスワード未設定を許容し、Google連携表を追加します。
4. 既存の実行専用ユーザーに、`user_credentials` のUPDATEと `google_accounts` のSELECT/INSERTだけを追加します。管理者権限やCREATE/DROP権限は与えません。
5. GitHubへ作業版を反映し、無料のRenderで公開更新します。Google設定未完了なら、その機能は無効のまま先にパスワード変更を公開できます。
6. 公開画面・HTTPS・既存ログイン・パスワード変更・再ログイン・下書き保持を確認します。Googleの設定完了後に、実際のGoogleアカウントで新規登録と既存連携を確認します。

本番用の更新手順は `tools/upgrade-account-security.py` に用意しています。バックアップ確認と所有者本人の非表示入力を要求し、想定外の移行履歴では停止します。削除・clean・自動baselineは行いません。失敗した状態を保持し、原因調査まで公開更新を止めます。

V4移行後は、古いコードへ戻すだけでGoogle専用アカウントを扱えるとは限りません。DBの逆移行やバックアップの復元は自動実行しません。
